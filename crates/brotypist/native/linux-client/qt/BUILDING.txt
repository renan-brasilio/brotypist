Activation boundary:
  Unset or empty BROTYPIST_NATIVE_BUS creates no BroTypist client. A nonempty
  value is a bus NAME on the existing session bus, never a bus address. The
  unique registered service owner alone can invoke the exported client methods.
  Registration/Event are asynchronous with bounded outstanding events, generation
  checks, owner-change/disconnect revocation, and owner-thread native access.
  No inference/model preparation or persistent user data lives in this adapter.

  A current authenticated, unexpired policy permits metadata-only toggle and
  app_toggle even when enabled=false. Disabled policy is retained for those
  bindings only: Capture, presentation, edits and force/alternatives/synonyms
  remain enabled/privacy/composition-gated. Expired/disconnected policy permits
  no owned action. The broker independently authorizes every action.
  Metadata/registration publish field_token, window_token, document_token and
  focus_generation. Actual focus/window/field/exported-block transitions
  withdraw policy immediately without unregistering the client. Live Configure
  must echo the exact fresh scope/generation; stale replies are refused. Inert
  expires_ns=0 always withdraws regardless of old scope. Ordinary input does not
  advance focus_generation. Action events freeze this scope plus policy_epoch
  before asynchronous broker authentication; no later-target substitution.
Target capabilities:
  QLineEdit, unmasked Normal echo: complete native text/cursor/selection witness.
  QTextEdit and QPlainTextEdit: complete public document/plain-text/cursor
  witness, matching the actual native current-block IM query. Native rich text
  remains owned by the host; commit/undo use its original IM-event semantics.
  Qt Quick TextInput, unmasked Normal echo: complete text/property witness
  cross-checked against native IM surrounding/cursor/anchor queries.
  Qt Quick TextEdit and ordinary QObject IM consumers: actual bounded native
  ImSurroundingText scope. ImAbsolutePosition - ImCursorPosition identifies a
  nonnegative native block origin; an opaque field+origin token identifies the
  exact exported scope. Selection must be wholly in that scope and exactly
  equal ImCurrentSelection. Unknown/truncated/cross-block selections refuse.
  No whole-document promise is made for a block-scoped document_token.
  Missing/unsafe native query contracts refuse; opaque custom undo internals
  alone do not exclude a conforming native IM consumer. Existing host undo is
  preserved, not emulated or strengthened if the host provides none.

Composition/presentation/edit authority:
  Hooks read the real in-process xkb_compose_state, actual user preedit list,
  per-focused-context client-side IM UI state, and outstanding native key RPC
  count. UI state updates occur only after original sender/window validation and
  are cleared with that context's candidate-window reset. Missing compose
  state or pending delivery is unknown. The original Fcitx key/Compose/dead-key/
  AltGr/Unicode path is unchanged for every non-owned key. AboveTab matches the
  original toolkit XKB native scan 49 for xcb/Wayland, never blindly adds eight.
  AltGr/GroupSwitch is not reinterpreted as Ctrl+Alt. Shortcut names and modifier
  spelling follow the shared Rust contract (word/all/force/app_toggle/toggle/
  alternatives/synonyms). Backtab normalizes to Tab while retaining Shift;
  keypad Enter normalizes to canonical Return.
  Ghosts are separately owned formatted QInputMethodEvents with empty commit
  strings; they never enter upstream preedit_/commitPreedit_ or its auto-commit
  buffer. Clear/reset/focus-out therefore cannot commit speculative text.
  User/foreign IM preedit is independently tracked from actual native events.
  Inline ghosts require the actual native text viewport, shaped glyph/underline
  ink and advance/whitespace bounds, LTR layout and one fully fitting line.
  QLineEdit uses its Qt6.12 style contents rectangle minus actual text margins;
  uninspectable side-widget/action margins, non-left/non-center alignment and
  visible child overlays refuse inline presentation. QTextEdit/PlainTextEdit use
  their real viewport and delivered block QTextLayout preedit/glyph runs.
  Quick TextInput requires native padding/baseline/font/clip, unwrapped left
  layout and a proven axis-aligned unit transform. Generic QObject/Quick
  TextEdit still support safe native chooser/edits but refuse inline ghosts
  without equivalent text-layout authority. Tabs/line separators/multiline,
  clipped ink and unknown geometry never authorize hidden text.
  Choosers use an actual transient, non-focus-taking QWindow/QBackingStore,
  including with QGuiApplication-only Quick apps. The same retained native
  QTextLayouts supply chooser painting and ink/advance measurements. Eligible
  fully fitting rows are compacted into an exact ordered subsequence of the
  offer, at most nine entries; an oversized/unsupported middle row does not
  suppress later fitting rows. Values are never elided, truncated or rewritten.
  Labels 1..n, navigation and clicks refer to compact displayed ordinals 0..n-1,
  NOT original offer indices. Core validates the entire nonempty shown_values
  subsequence with match_choice_subsequence and freezes a ChoiceMap from each
  displayed ordinal to its original offer index. Hidden rows have no authority.
  Duplicate values match successive offered occurrences in order.
  A chooser Present retains the original D-Bus request/reply serial, unique
  sender and registration/client identity as a pending delayed reply. It does
  not synchronously manufacture a receipt or spin a nested GUI loop. A real
  owner-loop exposed-window paint must complete all retained layouts through
  QPainter/QBackingStore before a fresh target/geometry/policy/lease recheck
  can issue the still-unarmed capability. Withdrawal/expiry resolves pending
  presentation with refusal; the original lease is never extended by waiting.
  Exposure alone is not owner paint, and withholding paint is not evidence of
  an actually unexposed window. These require separate native checks. Owner
  paint/flush is still not compositor-visible pixels or physical display proof;
  inline receipts attest native delivery/layout capability, not owner paint.
  Presentation is NOT acceptance authorization. Present always leaves the
  capability unarmed. Arm(a{sv})->b requires the same authenticated owner,
  offer/capability/policy epoch, exact original lease, exact shown_text and
  shown_values, and a fresh unchanged target witness plus native visibility.
  Only then may word/all/choice keys or clicks edit. Unarmed acceptance keys
  remain original events and unarmed popup rows cannot edit.
  Arm stores the core's exact word_text/all_text computed by the existing
  Suggestion::accept logic, including configured trailing space/punctuation.
  word_text/all_text exist only in Arm, never in the Present offer. The adapter
  does not reconstruct model acceptance from display text. Expiry-only policy
  renewal never arms a capability, and Arm never extends its original lease.
  Ghost and chooser have independent receipts, arming and expiry leases.
  Completion plus anchored alternatives can remain concurrently presented.
  Presenting/clearing/expiring a chooser does not clear a completion ghost;
  Clear(capability_id) removes only that receipt, while Clear(0) removes both.
  The same independence is required while a chooser Present reply is pending:
  unrelated inline offers and invalid/stale offers must not cancel that lane.
  Reentrant native queries must not permit a revoked/deleted popup, field or
  window to be dereferenced or receive a late success. The bounded native
  lifetime/lane scenarios passed in the private acceptance checkpoint below;
  this does not establish every custom host's query or lifetime behavior.
  Qt has one native in-field preedit slot. Correction replaces completion, and
  a completion requested while a live correction occupies that slot refuses
  with higher-priority-native-preedit rather than acknowledging hidden output.
  Word/all uses the live higher-priority ghost first. Only with no ghost may
  emoji/synonyms word/all choose displayed ordinal 0. Alternatives never steal
  word/all; arrows select a displayed ordinal and Enter/click accepts it.
  Chooser insertion is EXACT shown_values[ordinal], without trailing-space
  addition, and emits action=choice with choice_index equal to that displayed
  ordinal. Core's frozen ChoiceMap resolves the original offer identity; the
  adapter never sends an original offer index as a displayed choice_index.
  A live lease and fresh full witness are checked again for every owned key or
  choice click. Escape sends the frozen dismissed receipt; pause/app consume,
  passthrough leaves the original key. Expiry-only policy extensions do not
  clear a still-live ghost and never extend an existing offer's own deadline.
  Consumed presses retain a bounded, focus-scoped native key identity until the
  matching release; that release is consumed too, even after acceptance clears
  the chooser. Unmatched releases still go to Fcitx. Sending Fcitx an unmatched
  release starts async key processing (composition=unknown), which can revoke a
  still-armed chooser between Down and Return. Every new press still traverses
  the original policy, composition, witness, geometry and deadline guards.
  Widget key timestamps and auto-repeat flags are bounded observations, NOT
  injection provenance. In reviewed fcitx5-qt commit
  115750044f3d0db16ca5859808c7da830fd1ff52, ProcessKeyWatcher reconstructs
  QKeyEvent without copying its timestamp; processKeyEventFinished forwards
  that event through handleExtendedKeyEvent. createKeyEvent also reconstructs
  matched Qt6 events without their timestamps, and its unmatched branch sets
  auto-repeat=false. Therefore zero-time widget events and missing repeat
  flags can be native Fcitx replay, not fake or untimestamped XTest input.
  The smoke keeps real private-X11 XTest delivery and exact focus checks.
  Counters saturate at 4096 and describe post-Fcitx widget delivery only;
  no zero-time or repeat-flag count is required. Held-key repeat evidence is
  one injected keydown followed by additional widget presses before the sole
  injected keyup, with a subsequent observed release. Non-repeat cases retain
  exact press/release counts; consumed keys must not leak, revoked authority
  must remain unusable, and unowned releases/repeats must not commit or alter
  native text/caret/selection. The private Qt subset and canonical both-client
  run passed these bounded checks; production Metadata is unchanged.
  The owned Unicode smoke uses synonyms for a selected emoji and alternatives
  for a collapsed replacement. Native UTF16 active cursor 3/anchor 1 maps to
  canonical scalar selection start 1/length 1, not active scalar cursor 2.
  Its exact replacement is decomposed e + U+0301 + U+1F680 + space: expected
  native caret 6 and broker scalar caret 5. Each navigation press/release must
  leave the widget selection intact without leaking a key or revoking the
  chooser. One edit/report, duplicate rejection and one real XTest Ctrl+Z undo
  are required and passed in the private Qt subset and canonical both-client
  run. This does not alter the strict 15-field Metadata contract.
  Physical-scan release matching also passed modifier-release ownership: observed
  widget press/release totals were 1/1 after the consumed shortcut, 2/1 after an
  ordinary press and 3/3 finally. One broker toggle action was observed, with no
  Core toggle invocation, persistence, native commit or completion report.
  Ordinary native text/caret remained correct. This is exact-focus private-X11
  XTest evidence, not physical keyboard typing.
  One QInputMethodEvent::setCommitString performs an acceptance. A selected
  exact range uses (text,0,0), since Qt removes the existing selection itself;
  collapsed replacement uses (text,start-caret,length). No SetText, destructive
  delete/insert, retries or compensating edits. Before the sole dispatch, install
  one frozen pending receipt with the original acceptance timestamp, Arm text,
  range/action/index, policy, scope and lease. Unchanged immediate readback is
  NOT rejection: actual native notifications/queries resolve exact expected
  text/caret/selection, with a maximum 750ms native observation window and no
  redispatch. Lost/expired/divergent/unknown outcomes finalize indeterminate.
  Metadata.pending_edit stays true and public Capture stays empty until the
  final accepted Event RPC ACK succeeds; an async send is not acknowledgment.
  Proof is sent once to the original authenticated owner/client id. A successful
  ACK is conclusive even if the callback runs late. Timeout/error retains the
  single unconfirmed receipt/quarantine rather than exposing generated text as
  authored. Failure recovery is deliberately not an implicit retry/reset.
  Final proof precedes own changed notification. Nested real user input changes
  user_revision and is never silently classified as generated output.

Short fixed refusal reasons include:
  unauthorized; stale-or-unsupported-target; disabled-feature; invalid-range;
  selection-range-mismatch; unavailable-native-geometry;
  preedit-not-fully-visible; native-preedit-refused; invalid-choices;
  choices-not-fully-visible; target-changed-during-presentation; expired;
  higher-priority-native-preedit.
  Capture returns an empty dictionary for disabled/stale/protected/composing,
  oversize, malformed-UTF16, unsupported-query or ambiguous-scope targets.

Diagnostic coverage boundary:
  native_client_smoke --client gtk or --client qt selects one mandatory client
  for diagnosis, not a replacement acceptance suite. Receipts identify the
  requested and covered client and canonical_both=false for a subset. Default
  invocation / --client both still requires both private plugins and fixtures,
  with both clients passing; missing prerequisites or refusals fail, not skip.
  Neither a successful subset nor a successful build establishes canonical
  both-client acceptance. No private staging paths or probe recipes are needed
  to interpret this boundary.
  Exercised Qt scenarios include compact choices/refusals, selected and collapsed
  non-BMP/NFD replacement with one commit and validated report each plus native
  undo, live Arm/Down/Return query hide/destroy withdrawal, unmatched release,
  held-key repeat, focus roundtrip and modifier-release ownership. Owner-paint,
  independent pending lanes, reentrant paint/final-query hide/destroy, deadline,
  hide/focus/move/minimize/policy/destroy and orderly broker-disconnect checks
  also passed. Minimize observed the TARGET unexposed; it did not observe an
  unexposed popup. Withheld paint observed an exposed popup and is not proof of
  a genuinely unexposed popup. Orderly disconnect clears receipts first and
  does not establish isolated abrupt owner-loss behavior.
